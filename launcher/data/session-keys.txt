# on the command line: the layer places and sizes the stereo window (ETERNALVR_WINDOW), the game saves

# would open there, off screen. The launcher snapshots them and puts them back after the session like the
# forced cvars (a key that was absent is removed); a change the player makes to them in VR is undone too.

# Knock-on keys: the game changes and saves these itself because of a stereo setting (runs on a second
# test PC, 2026-09-27, config before and after each run): r_SSDO 0 and r_SSR 0 follow r_TAASafeMode 1
# (0x1C6FCC0; the layer holds it while per-eye TAA is not active, and in the v1 fallback), r_blurRadialScale
# 1 follows the forced r_motionblur 0. A player's flat game must not keep them. In stereo the layer holds
# r_SSDO at the player's own value (ETERNALVR_STEREO_SSDO), r_SSR too while per-eye TAA runs
# (ETERNALVR_STEREO_SSR), and r_blurRadialScale at 0 with the comfort set (no dash zoom blur), which the
# restore puts back either way. r_SSDO and r_SSR are kept as the game saved them when the layer held them at the
# player's own Directional Occlusion and Reflections settings (LaunchPlan.KeptKeys, confirmed by the layer's
# status file: ssr_follow / ssdo_follow, and saved at the value it held, ssr_value / ssdo_value, a key left out
# of the config counting as its default 1), so a change made in the game's menu during the session stays.
r_SSDO
r_SSR
r_blurRadialScale
